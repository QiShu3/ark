## 1. Demo 简介

### 是什么
Ark 是一款以「专注工作 + 学习成长」为核心的个人效率与学习平台。它将番茄钟专注工作流、智能记忆算法（FSRS）、考研英语阅读训练、词汇背诵、任务事件管理、成就系统等功能整合在一个统一的沉浸式界面中，辅以角色立绘和对话交互，打造游戏化的学习体验。

### 面向谁
- **考研/考证党**：需要长期坚持英语阅读、词汇背诵的学习者
- **自由职业者/学生**：需要番茄钟专注工作来提升效率的人群
- **自我提升爱好者**：喜欢用数据和成就系统驱动自己成长的人

### 主要功能

#### 功能一：统一专注工作引擎
- 四种专注工作类型：闪卡背诵、选择题训练、输入题练习、任务专注
- 多阶段工作流：专注 + 休息交替，支持番茄钟和自定义模式
- 实时数据统计：正确率、答题数、耗时、重试次数一目了然
- 可最小化/全屏，专注不被打断

#### 功能二：智能词汇学习（FSRS 算法）
- 基于 FSRS（自由间隔重复调度）算法的智能复习调度
- 新词学习 + 复习 + 错词本，完整学习闭环
- 多词书切换，支持词书继承
- 今日单词一键开启专注模式

#### 功能三：考研英语阅读训练（ERC）
- 文章 + 选择题的完整阅读训练模式
- 按题库顺序推进，支持 Set 快照存档
- 已做题目自动进入 FSRS 复习池
- 文章/段落/题目三级种子导入，轻松扩展题库

#### 功能四：事件驱动的目标管理
- 围绕「事件」（考试、项目等长期目标）组织任务
- 任务自动纳入每日专注，完成即计入进度
- 日历视图、倒计时卡片、多周规划
- 成就系统：全局成就 + 事件成就，解锁成就感

#### 功能五：沉浸式 UI 设计
- 左侧角色立绘面板，可自定义角色和背景
- 底部对话交互，降低学习枯燥感
- 右侧仪表盘：日历、任务、计时、快速启动
- 多主题支持，玻璃拟态设计风格

## 2. Demo 创作思路

### 灵感来源
作为一个长期在备考和自我提升路上的人，我发现市面上的学习工具大多是「单点功能」——背单词一个 App、做阅读一个 App、番茄钟又一个 App。数据分散、体验割裂，每次切换都打断心流。而且大多数工具缺乏「温度」，就是冷冰冰的功能堆砌，很难让人长期坚持。

我想要一个**一体化的学习系统**：打开一个地方，就能管理我的学习目标、开始专注、追踪进度、获得反馈。最好还能有点「陪伴感」，让学习不那么孤独。

### 想解决的问题
1. **工具碎片化**：背单词、做阅读、番茄钟、任务管理分散在不同 App，数据不互通
2. **难以坚持**：学习过程枯燥，缺乏正向反馈和成就感
3. **目标模糊**：只有待办清单，没有围绕长期目标（如考研）的系统性规划
4. **记忆低效**：传统的复习方式要么复习太多浪费时间，要么复习太少记不住

### 为什么做这个方向
- **真实痛点**：我自己就是目标用户，每天都在跟这些问题打交道
- **技术可行**：用 TRAE 可以快速把想法变成可运行的原型
- **有独特性**：把「统一专注引擎 + FSRS 智能记忆 + 事件驱动目标管理 + 沉浸式 UI」组合在一起的产品并不多
- **可扩展性强**：应用注册表架构，以后可以轻松加入新的学习模块

## 4. TRAE 实践过程

### 整体开发流程

整个 Ark 项目的开发都是在 TRAE IDE 中完成的，从 0 到 1 搭建了前后端完整架构。开发过程大致分为几个阶段：

1. **项目初始化与架构设计**：确定前后端技术栈，搭建基础框架
2. **核心引擎开发**：实现统一专注工作引擎和 FSRS 记忆算法
3. **功能模块开发**：词汇学习、ERC 阅读训练、任务事件系统
4. **UI/UX 打磨**：沉浸式界面、角色系统、主题切换
5. **功能完善**：成就系统、签到、应用注册表等

### 开发心得

用 TRAE 开发最大的感受是「快」和「顺」。

**快**体现在：很多以前需要自己查文档、写样板代码的工作，TRAE 可以直接帮你生成。比如 FSRS 算法的实现、数据库表结构设计、API 接口编写，这些都可以快速搞定，让我把精力集中在产品逻辑和用户体验上。

**顺**体现在：TRAE 不是简单的代码生成，而是能理解整个项目的上下文。当我要加一个新功能时，它知道已有的架构是怎样的、应该遵循什么规范、放在哪个目录下，不会东一榔头西一棒子。

印象最深的是「应用注册表」这个设计。一开始每个模块都是各自为政的，后来想做统一的应用中心，TRAE 帮我梳理了前后端统一注册机制的设计思路，从数据模型到 API 接口再到前端动态渲染，一套下来非常顺畅。

当然也踩过不少坑，比如 FSRS 算法和现有题库的适配、专注工作流的状态管理、多主题 CSS 变量的设计等等。但每次遇到问题，把报错和上下文扔给 TRAE，它都能快速定位问题、给出解决方案，大大缩短了调试时间。
