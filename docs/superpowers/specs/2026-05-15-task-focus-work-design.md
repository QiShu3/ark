# 自定义任务专注工作并入统一专注运行时设计

## 1. 背景

- 当前“专注工作”只覆盖子应用型专注内容：
  - `vocab_today`
  - `erc_review`
- 工作流的 `focus` 阶段除了可绑定子应用专注任务外，也可以绑定自定义任务。
- 但当工作流进入自定义任务阶段时，当前系统只会：
  - 绑定 `task_id`
  - 启动任务专注计时
  - 在顶部胶囊中显示任务标题与计时状态
- 当前系统不会为自定义任务打开专属专注界面，因此“自定义任务专注”与“子应用专注工作”仍是两套体验。

## 2. 本次目标

- 让自定义任务也进入统一的“专注工作”体系。
- 为自定义任务提供专属的沉浸式专注页。
- 保持当前顶部胶囊、工作流阶段推进、结果提交流程的整体结构不变。
- 新增 `暂停专注 / 继续专注` 能力，但仅对任务型专注开放。

## 3. 当前确认的产品结论

### 3.1 专注工作不再只等于子应用工作

- “专注工作”升级为统一的专注运行时。
- 第一版统一纳入三类专注工作：
  - `vocab_today`
  - `erc_review`
  - `task_focus`

### 3.2 自定义任务采用极简沉浸页

- 默认主视觉只突出：
  - `任务名`
  - `计时器`
- 任务细节默认折叠。
- 用户可主动展开任务备注、子任务等只读信息。
- 第一版不把该页面做成任务管理台或任务编辑器。

### 3.3 自定义任务专注页的结束动作

- 主按钮：`完成本轮专注`
- 次按钮：`完成任务并结束专注`
- 风险按钮：`放弃本阶段`

### 3.4 新增暂停语义

- 页面按钮文案统一为：
  - `暂停专注`
  - `继续专注`
- `暂停专注` 的定义：
  - 停止当前专注阶段计时
  - 保持当前阶段不结束
  - 不进入 `pending_confirmation`
  - 不退出当前专注工作页
  - 后续可继续当前同一阶段

### 3.5 暂停态的页面表现

- 点击 `暂停专注` 后，专注工作页不关闭。
- 原专注内容仍保留在后方，但整体明显变暗、弱化。
- 页面中央出现克制的暂停层。
- 暂停层主按钮为 `继续专注`。

## 4. 与现有能力的边界

### 4.1 不复用 `skip_phase` 作为暂停

- 当前 `/todo/focus/workflow/skip_phase` 的语义是：
  - 结束当前阶段剩余计时
  - 将工作流置为 `pending_confirmation`
  - 等待用户确认流转到下一阶段
- 该行为等价于“提前结束当前阶段”，不等价于“暂停当前阶段”。
- 本次设计必须保持两者语义分离：
  - `skip_phase`：结束阶段
  - `pause_focus_work`：冻结阶段

### 4.2 第一版不扩展到 Vocab 与 ERC 的暂停

- `暂停专注 / 继续专注` 第一版仅对 `task_focus` 开放。
- `vocab_today` 与 `erc_review` 保持现状，不强行套入暂停态。

### 4.3 第一版不扩展统计与复盘

- 不新增阶段历史面板。
- 不新增专注统计分析面板。
- 不新增任务执行建议或自动总结。

## 5. 架构设计

### 5.1 统一运行时思路

- 继续复用现有前端专注运行时：
  - `FocusWorkProvider`
  - `FocusWorkModalShell`
  - `focusWorkRegistry`
- `focusWorkRegistry` 新增 `task_focus` 定义。
- 工作流进入绑定自定义任务的专注阶段时，不再只绑定 `task_id` 后停留在原页面。
- 系统需要像进入 `vocab_today` 或 `erc_review` 一样，进入统一的全屏专注工作容器。

### 5.2 运行时上下文

- `task_focus` 需要在统一专注运行时中拿到当前任务上下文：
  - `task_id`
  - `task_title`
  - 任务补充信息（备注、子任务等）
- 任务内容由当前活动工作流快照提供，不额外引入第二套任务来源。

### 5.3 工作流阶段与专注工作的对应关系

- 当 `focus` 阶段绑定 `focus_work_type` 时：
  - 按既有子应用专注逻辑进入专注工作
- 当 `focus` 阶段绑定的是自定义任务时：
  - 统一映射为 `task_focus`
  - 并带上当前任务上下文

## 6. 状态模型

### 6.1 维持工作流主状态三态

- 工作流主状态继续保持：
  - `normal`
  - `focus`
  - `break`
- 不把 `paused` 做成新的主状态值，避免扩大现有状态机改动面。

### 6.2 使用附加暂停字段

- 在工作流快照中新增附加字段：
  - `is_paused`
- 语义为：
  - 当 `state === 'focus' && is_paused === true` 时，表示当前仍在该专注阶段内，但计时暂停。

### 6.3 暂停态行为

- 暂停后：
  - `current_phase_index` 不变
  - `task_id` 不变
  - `active_focus_work_type` 保持为 `task_focus`
  - 当前专注页仍打开
  - 前端计时器冻结
- 恢复后：
  - 继续当前同一阶段
  - 不创建新阶段
  - 不重置当前任务上下文

## 7. 页面交互

### 7.1 默认态

- 顶部区域：
  - 轻量阶段标签
  - 很弱的记录状态提示
- 主体区域：
  - 大号任务名
  - 大号计时器
- 次级区域：
  - 默认折叠的任务细节区
- 底部操作区：
  - `暂停专注`
  - `完成本轮专注`
  - `完成任务并结束专注`
  - `放弃本阶段`

### 7.2 任务细节区

- 默认折叠。
- 展开后只读展示：
  - 任务备注
  - 子任务 / checklist
- 第一版不在专注页内直接编辑任务内容。

### 7.3 暂停态

- 点击 `暂停专注` 后：
  - 中断当前计时推进
  - 页面主体不卸载
  - 背景专注内容整体压暗
  - 中央显示暂停层
- 暂停层仅保留一个清晰主动作：
  - `继续专注`

## 8. 动作语义

### 8.1 完成本轮专注

- 结束当前专注阶段。
- 进入现有阶段流转逻辑。
- 不自动将任务标记为完成。

### 8.2 完成任务并结束专注

- 先将当前任务标记完成。
- 再结束当前专注阶段。
- 进入现有阶段流转逻辑。

### 8.3 放弃本阶段

- 沿用现有专注结果语义中的放弃逻辑。
- 结束当前专注阶段，但结果记为 `abandoned`。

### 8.4 暂停专注

- 不结束当前阶段。
- 不推进工作流。
- 不退出专注工作页。
- 只让当前任务型专注进入暂停态。

### 8.5 继续专注

- 从暂停态恢复当前阶段计时。
- 保持当前专注页、任务上下文与阶段位置不变。

## 9. 后端设计

### 9.1 数据模型增量

- `FocusWorkType` 扩展为包含 `task_focus`。
- 活动工作流快照增加暂停字段：
  - `is_paused BOOLEAN NOT NULL DEFAULT FALSE`
- 活动工作流同时增加：
  - `paused_at TIMESTAMPTZ NULL`
- 暂停时写入 `paused_at = NOW()`。
- 恢复时通过 `NOW() - paused_at` 的暂停时长，顺延当前阶段的 `phase_started_at`，再清空 `paused_at`。
- 第一版必须保证恢复后剩余时间与累计时间准确衔接。

### 9.2 新接口

- 新增暂停接口：
  - `POST /todo/focus/workflow/pause`
- 新增恢复接口：
  - `POST /todo/focus/workflow/resume`

### 9.3 阶段进入逻辑

- 当工作流推进到自定义任务专注阶段时：
  - 当前阶段应写入统一专注运行时字段
  - `active_focus_work_type = task_focus`
  - 专注显示状态默认进入 `fullscreen`

### 9.4 结果与暂停的关系

- `completed / interrupted / abandoned` 仍用于阶段结束结果。
- `paused` 不属于阶段结束结果。
- 暂停只是一种阶段内运行态。

## 11. 测试策略

### 11.1 后端测试

- 自定义任务专注阶段会打开 `task_focus` 运行时快照。
- `pause` 后：
  - 阶段不流转
  - `is_paused = true`
  - 计时冻结
- `resume` 后：
  - `is_paused = false`
  - 恢复同一阶段计时
- `完成本轮专注` 会推进现有阶段流转。
- `完成任务并结束专注` 会同时完成任务并推进阶段。

### 11.2 前端测试

- 自定义任务阶段打开统一专注页。
- 默认只突出任务名与计时器。
- 任务细节默认折叠，可展开。
- 点击 `暂停专注` 后显示暂停遮罩。
- 暂停态主按钮文案为 `继续专注`。
- 顶部胶囊在暂停态下展示正确文案并停表。

## 12. 非目标

- 不做第二套独立的任务专注框架。
- 不把专注页做成完整任务执行台。
- 不重做现有工作流阶段编辑器的大结构。
- 不在第一版中为所有专注类型引入统一暂停机制。

## 13. 推荐实施顺序

1. 打通 `task_focus` 类型与工作流进入逻辑。
2. 完成任务型专注页的极简渲染。
3. 增加 `pause / resume` 后端接口与快照字段。
4. 接入前端暂停遮罩与胶囊停表逻辑。
5. 补齐阶段完成、任务完成、放弃本阶段的联动测试。
