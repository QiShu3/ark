# Ark 子应用模板共性设计

## 背景

本文记录 Ark 子应用的共性模型，用于指导未来子应用设计。这里讨论的是产品和业务规则，不涉及具体代码实现。

Ark 子应用不是一个独立页面，也不是一个普通功能按钮，而是绑定在事件上的完整业务系统。子应用通过事件应用配置定义目标，通过子应用任务承载执行，通过专注工作完成业务动作，最后把结果回写到事件、任务、成就和复盘体系中。

## 核心关系

每个完整子应用都应遵守以下关系：

```text
事件
  -> 子应用配置
    -> 子应用任务
      -> 专注工作
```

业务含义如下：

- 事件是最高归属。子应用产生的任务、日程、成就、专注记录、业务进度和复盘摘要，最终都应绑定到某个事件。
- 子应用配置是中心。一个事件下，每个子应用默认只有一份配置。配置定义该子应用在该事件里的目标、范围、节奏和生成规则。
- 子应用任务由配置派生。它承载这个事件下今天或本周期要完成什么。
- 专注工作绑定任务。专注工作不是凭空启动的，用户进入专注，本质上是在执行某个子应用任务。
- 子应用任务绑定专注工作。每个可执行的子应用任务都应知道自己进入哪类专注工作。

一句话概括：

> 子应用配置生成子应用任务，子应用任务绑定专注工作，专注工作完成后反过来推动任务完成。

## 子应用配置

子应用配置是事件下某个子应用的唯一源数据。

它定义：

- 子应用在该事件里的目标。
- 子应用使用的资源范围。
- 每日或每周期的节奏。
- 任务、日程、成就的生成规则。
- 默认专注时长或执行偏好。
- 进度和复盘的统计口径。

例如：

- 背单词配置可以包含词书、每日目标、复习节奏、默认专注时长。
- 阅读训练配置可以包含题库范围、每日文章数、错题复习量、默认专注时长。

无论用户在事件工作台修改，还是在子应用首页修改，改的都应该是同一份事件应用配置。两处入口只是不同操作面，不应产生两份状态。

## 派生内容

子应用根据配置派生业务对象。

常见派生内容包括：

- 任务：承载可执行目标，例如今日单词、真题练习、错题复习。
- 日程：安排时间、提醒节奏或规划执行窗口。
- 成就：反馈事件推进、连续完成、累计成果。
- 进度摘要：展示当前事件下该子应用完成了什么、还剩什么、推进了多少。

这些内容都应绑定事件，而不是孤立存在。

## 子应用任务与专注工作

完整子应用必须提供专注工作。

专注工作是用户真正开始做事的地方。专注工作应绑定到某个子应用任务上；子应用任务也应绑定到对应的专注工作。

例如：

```text
背单词配置
  -> 今日单词任务
    -> 今日单词专注工作

阅读训练配置
  -> 真题练习任务
    -> 真题练习专注工作

阅读训练配置
  -> 错题复习任务
    -> 错题复习专注工作
```

专注工作外壳只管理通用专注过程，例如暂停、继续、放弃本阶段、结束本次专注。它不判断业务任务是否完成。

任务是否完成，由子应用自己判断。

核心原则：

> 专注外壳管理时间，子应用管理完成。

## 完成判定

结束专注不等于完成任务。

用户点击专注外壳上的“结束本次专注”，只表示这一段专注时间结束。它可以记录专注时长，可以推动工作流进入休息或下一阶段，但不应直接触发任务完成。

任务完成应由子应用根据业务目标判断。

例如：

- 背单词：只有完成今日配置目标，才算今日单词任务完成。
- 真题练习：只有提交整篇练习并得到结果，才算真题练习任务完成。
- 错题复习：只有完成本次或今日配置题量，才算错题复习任务完成。

业务边界：

```text
结束专注 ≠ 完成任务
业务目标达成 = 任务完成
```

## 三类记录

一次子应用专注工作可能产生三类记录。未来子应用开发必须明确区分这三类记录，不能混成一个。

### 专注记录

专注记录回答：

> 用户有没有投入一段专注时间？

它记录开始、暂停、继续、结束、中断、放弃、持续时长等专注过程信息。它归 Ark 的专注系统管理。

### 任务完成记录

任务完成记录回答：

> 事件下这项子应用任务今天或本周期是否完成？

它由子应用在业务目标达成时触发完成信号，再由 Ark 记入任务和事件体系。

### 子应用业务记录

子应用业务记录回答：

> 业务本身发生了什么？

它保存子应用自己的业务结果，例如背了哪些词、哪些词答错、练了哪篇文章、哪些题进入错题、复习算法如何推进。

它归子应用自己的业务系统管理。

重要边界：

```text
结束专注 ≠ 完成任务
完成任务 ≠ 业务记录全部细节
业务记录可以持续保存，即使任务未完成
```

例如，用户背单词背到一半退出：

- 有专注记录：用户专注了多久。
- 有业务记录：已经背过的词和作答结果要保存。
- 没有任务完成记录：今日单词还没完成。

用户完成今日单词：

- 有专注记录：本轮专注完成。
- 有业务记录：今日所有词的学习结果保存。
- 有任务完成记录：今日单词任务完成，事件进度推进。

## 进度复盘

完整子应用必须能提供进度复盘。

进度复盘应回答：

- 这次做了什么。
- 完成了什么。
- 还剩什么。
- 对当前事件推进了多少。
- 哪些任务、日程、成就发生了变化。
- 下次应该继续做什么。

复盘信息应能出现在两个地方：

- 子应用首页：展示当前主事件下该子应用的进度和下一步入口。
- 事件工作台：展示该事件下所有子应用的安排、进度和成果。

## 子应用首页统一模板

子应用首页是用户查看当前主事件下该子应用状态的单页工作台。它不是营销页，也不是功能入口集合。页面应围绕事件应用配置、业务数据和托管安排展开。

统一顺序固定为：

```text
顶部配置入口
  -> 总览
  -> 业务数据
  -> 托管安排
```

这套模板只约束子应用内容区，不包含 Ark 全局导航、左侧/右侧面板或顶部工作流胶囊。

### 1. 顶部配置入口

顶部区域负责回答：

> 当前子应用绑定到哪个事件？是否已经可配置？

应包含：

- 子应用用户侧名称，例如“背单词”“阅读训练”。
- 当前计划事件状态，例如“已绑定计划事件”“未绑定计划事件”“待配置计划事件”。
- 当前绑定事件名称，例如“计划事件：考研英语”。
- 子应用当前关键上下文的简短摘要，例如当前词书、托管任务名称。
- 唯一页面级配置按钮，统一命名为“配置”。

如果没有主事件，或当前主事件尚未配置该子应用，应使用注释文本提示用户。注释文本使用统一的 annotation 样式，不使用临时的警告色散落在页面中。

顶部区域不应放置：

- “开始/继续专注”按钮。
- 题库、错题、快捷练习等业务跳转按钮。
- “当前任务”独立模块。
- 营销式 hero 说明文案。

### 2. 总览

总览区域负责回答：

> 今天或当前周期最核心的进度是什么？

总览使用 3-4 个轻量指标卡展示当前周期状态。指标应来自该子应用已有 summary/status/overview 数据，不为首页单独引入复杂状态。

示例：

- 背单词：今日进度、待完成、新词、复习。
- 阅读训练：今日待复习、已练文章、正确率、错题。

总览指标卡可以有轻微 hover 反馈，用于表达“可扫视的指标块”。外层背景板不应有 hover 高亮，避免用户误以为整块区域可被选中或点击。

### 3. 业务数据

业务数据区域负责回答：

> 这个子应用沉淀了哪些用户业务资产？用户可以从哪里查看明细？

这里展示子应用自己的长期数据、明细入口和业务资产，而不是任务执行入口。

示例：

- 背单词：已完成词书、累计掌握、当前词书掌握度、未开始/学习中/已掌握明细。
- 阅读训练：题库进度、错题资产、今日推荐练习。

业务数据可以包含跳转或明细弹窗，但跳转目标应是业务查看或业务管理，例如题库、错题本、概览明细。它不应承担“开始专注”的主入口。

### 4. 托管安排

托管安排区域负责回答：

> 这个子应用替当前主事件托管了哪些任务和日程？用户现在能执行什么？

托管安排使用统一展示组件承载任务和日程。任务行应包含：

- 任务名称。
- 绑定的专注工作名称。
- 状态 chip。
- 是否同步到今日安排；如果该子应用强制同步，则隐藏开关并在保存配置时固定同步。
- 主操作按钮。
- 不可执行时的阻塞原因。

任务主操作建议遵守以下状态语义：

| 状态 | 展示语义 | 主操作 |
|---|---|---|
| `no_primary_event` | 需要主事件 | 禁用 |
| `event_not_configured` | 未配置 | 配置 |
| `config_invalid` | 配置异常 | 配置 |
| `uninitialized` | 未初始化 | 初始化，或进入配置 |
| `ready` | 可执行 | 开始 / 继续 |
| `completed_today` | 当前周期已完成 | 配置 |
| 任务被用户关闭 | 未启用 | 配置 |

专注工作入口只应出现在托管安排的任务行中。不要在页面顶部、总览区或业务数据区再放一个独立的“开始/继续”入口。

日程区域展示该子应用托管的日程。没有数据源时可以显示“暂无日程安排”的空状态，但不要伪造日程，也不要在托管安排之外提供对应用托管日程的 CRUD。

## 配置弹窗

点击页面级“配置”按钮后，应打开子应用配置弹窗。配置弹窗对应的是事件应用配置，而不是普通页面设置。

配置弹窗应包含：

- 当前事件绑定信息。没有主事件时，应阻止继续配置或引导用户先绑定主事件。
- 子应用上下文配置，例如词书、题库范围、复习范围。
- 任务配置，例如启用/停用任务、每日目标、默认专注时长、是否同步到今日安排。
- 日程配置，如果该子应用会托管日程。
- 保存按钮，命名为“保存配置”。

保存配置后，应触发同一套派生逻辑：

```text
保存事件应用配置
  -> 校验子应用上下文
  -> 派生或更新应用托管任务
  -> 派生或更新应用托管日程
  -> 刷新首页 summary / overview / task status
```

子应用派生的任务和日程都绑定主事件和子应用。除非进入子应用配置，否则不应在普通任务/日程 CRUD 中直接编辑它们的核心派生属性。

## 页面反模式

为了保持不同子应用之间的一致性，首页应避免以下模式：

- 用大 hero 或双栏宣传区替代真实工作台。
- 把配置入口命名为“Settings”“安排管理与设置”等不一致文案。
- 同时存在多个页面级配置入口。
- 在托管安排之外放置独立的“开始今日任务”“继续任务”“初始化任务”按钮。
- 把新词、复习、错题等快捷入口平铺成入口集合，稀释业务数据和托管安排的层级。
- 展示用户无法判断意义的内部算法比例或调度明细。
- 让外层背景板出现 hover 选中态。
- 用临时颜色样式展示注释说明，导致夜间模式可读性不稳定。

## 配置同步

子应用配置可以从事件工作台或子应用首页修改。无论从哪里修改，都应更新同一份事件应用配置，并触发同一套同步逻辑。

同步过程应包括：

```text
更新子应用配置
  -> 校验配置
  -> 更新任务
  -> 更新日程
  -> 更新成就
  -> 更新进度摘要
```

默认同步原则：

- 系统生成且未被用户手动改过的任务、日程、成就，可以自动更新。
- 用户手动调整过的任务或日程，不应被强行覆盖。
- 当配置和已生成内容发生冲突时，应保留用户修改，或提示用户处理差异。

## 子应用模板总结

一个完整 Ark 子应用，是围绕事件应用配置展开的完整执行系统：

1. 事件提供归属。
2. 子应用配置定义目标和规则。
3. 子应用配置派生任务、日程和成就。
4. 子应用任务绑定专注工作。
5. 用户通过任务进入专注工作。
6. 专注外壳管理时间，子应用判断完成。
7. 一次专注工作产生专注记录、任务完成记录和子应用业务记录。
8. Ark 将任务完成写回事件、今日计划、成就和复盘体系。
9. 用户可以在事件工作台或子应用首页调整配置，派生内容随配置同步。

这套共性模型是未来讨论不同子应用能力差异的基础。
