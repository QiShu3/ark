# 主页面开始工作流入口重构设计

## 1. 背景

主页面右侧第一张卡当前承担“开始专注”的快捷入口。它的实际行为是自动挑选一个今日任务，然后调用任务专注接口；后端再套用默认工作流并进入专注阶段。

这个行为底层已经接入工作流，但用户看到的语义仍然是“开始某个任务的专注”，不是“开始工作流”。本次重构要把这个入口改成工作流优先的启动器：用户先选择一个工作流，以后点击入口就直接启动该工作流。

## 2. 本次目标

- 将主入口从 `开始专注` 重构为 `开始工作流`。
- 入口默认绑定“上次选择的工作流”，点击后直接启动该工作流。
- 入口副文案显示当前选择的工作流名称。
- 点击工作流名称可以切换当前选择的工作流。
- 切换面板保持轻量，只包含工作流列表和 `新建工作流`。
- `新建工作流` 复用现有工作流预设管理面板，不在启动面板中编辑预设。

## 3. 产品语义

### 3.1 启动工作流不是新建工作流

用户点击 `开始工作流` 时，产品语义是“按当前选择的预设启动工作流”。

技术实现仍需要在后端保存一次活动运行态，用于承载：

- 当前阶段
- 阶段计时
- 任务选择状态
- 暂停/恢复状态
- 阶段结果与流转

这条运行态不是新的工作流预设，用户不应该感知为“创建工作流”。文案中统一使用 `启动工作流`、`当前工作流`、`选择工作流`，避免出现“创建活动工作流”这样的产品表述。

### 3.2 主入口是一键启动

当当前没有运行中的工作流时，主入口显示：

- 主文案：`开始工作流`
- 副文案：当前选择的工作流名称

用户点击主入口后，立即启动当前选择的工作流，不再弹出确认面板。

### 3.3 副文案承担切换能力

副文案显示当前选择的工作流名称，例如 `深度工作流`。点击这个名称时打开轻量选择面板。

选择面板只负责切换“当前选择的工作流”。用户点击某个预设后：

- 记录该预设为当前选择
- 关闭选择面板
- 不自动启动工作流

这样主入口的动作保持稳定：点 `开始工作流` 才启动，点工作流名称只是切换。

## 4. 当前选择规则

当前选择的工作流按以下优先级解析：

1. 用户上次手动选择的工作流。
2. 后端标记为默认的工作流。
3. 最近更新的第一个工作流。
4. 如果没有任何工作流，入口显示空状态并引导新建。

上次选择使用前端本地持久化保存，不改变后端默认工作流设置。这样“上次选择”和“默认预设”是两个概念：

- `默认工作流` 是后端预设属性。
- `当前选择的工作流` 是主页面启动器的最近使用偏好。

如果上次选择的预设已被删除，前端自动回退到默认工作流或最近更新的预设。

## 5. 空状态

当用户没有任何工作流预设时：

- 主文案显示 `新建工作流`
- 副文案显示 `还没有可启动的工作流`
- 点击主入口直接打开现有工作流预设管理面板

该状态下不展示轻量切换面板，因为没有可切换对象。

## 6. 工作流切换面板

切换面板是一个轻量弹层，不是新的管理台。

内容包括：

- 标题：`选择工作流`
- 工作流预设列表
- 当前选中项标记
- `新建工作流` 按钮

每个预设项展示：

- 工作流名称
- 阶段数量
- 是否为默认工作流

点击预设项只切换当前选择，不启动。

点击 `新建工作流` 时：

- 关闭切换面板
- 打开现有 `工作流预设` 管理面板

## 7. 启动行为

### 7.1 正常启动

当用户点击 `开始工作流` 且存在当前选择的预设时，前端调用按预设启动接口。

推荐接口：

`POST /todo/focus/workflows/{preset_id}/start`

后端负责：

- 校验预设属于当前用户
- 校验当前没有活动工作流
- 读取预设阶段配置
- 启动该预设对应的一次运行态
- 返回最新工作流快照

前端收到快照后：

- 刷新主页面入口状态
- 触发 `ark:reload-focus`
- 让顶部胶囊与专注运行时同步进入对应状态

### 7.2 第一阶段已绑定任务或专注工作

如果预设第一阶段可以直接进入专注：

- 第一阶段绑定了任务，进入该任务的专注工作。
- 第一阶段绑定了页面级专注工作，进入对应专注工作。
- 顶部胶囊与专注运行时沿用现有 `focus` 状态展示。

### 7.3 第一阶段需要选择任务

如果预设第一阶段是未绑定任务的 `focus` 阶段，启动后进入现有 `pending_task_selection` 状态。

前端表现为：

- 顶部胶囊显示 `选择任务`
- 主页面入口显示当前工作流正在等待选择任务
- 用户使用现有任务选择弹窗绑定当前阶段任务

这保持了启动面板的简单性，也复用现有工作流选任务机制。

### 7.4 已有活动工作流

当已有活动工作流时，主页面第一张卡继续显示运行态控制，不显示 `开始工作流` 入口。

后端启动接口如果收到重复启动请求，应返回冲突错误，不自动覆盖当前工作流。

## 8. 与现有功能的关系

### 8.1 工作流预设管理面板

现有 `WorkflowPresetModal` 继续负责：

- 创建工作流
- 编辑工作流
- 复制工作流
- 删除工作流
- 设置默认工作流

本次不把这些管理能力复制到启动面板中。

### 8.2 顶部工作流胶囊

顶部工作流胶囊继续负责运行态展示和阶段流转提示。

本次主页面入口重构不改变：

- `pending_confirmation`
- `pending_task_selection`
- `pause/resume`
- `skip_phase`
- 专注工作全屏锁定

启动后所有运行态仍以顶部胶囊和 `FocusWorkProvider` 的快照为准。

### 8.3 任务专注入口

旧的“自动挑一个今日任务并开始专注”不再作为主页面第一入口的默认行为。

如果后续仍需要“快速开始今日任务”，应作为任务列表或今日任务区域里的专门动作，而不是混在 `开始工作流` 主入口中。

## 9. 前端设计

### 9.1 状态

主页面入口需要新增：

- `selectedWorkflowPresetId`
- `showWorkflowPicker`
- `startingWorkflow`

`selectedWorkflowPresetId` 持久化到 localStorage。建议 key：

`ark-home-selected-workflow-preset-id`

### 9.2 有效当前工作流

从 `workflowPresets` 中派生 `effectiveSelectedWorkflow`：

1. 匹配本地保存的 `selectedWorkflowPresetId`。
2. 找不到时使用 `is_default` 的预设。
3. 仍找不到时使用最近更新的预设。

该派生值决定入口副文案与启动目标。

### 9.3 点击区域

第一张卡的顶部主区域拆成两个语义动作：

- 主点击区：启动当前工作流。
- 工作流名称/切换入口：打开切换面板。

切换入口需要阻止事件冒泡，避免用户想切换时误启动。

### 9.4 错误反馈

启动失败时显示明确错误：

- 没有工作流：打开预设管理面板。
- 已有活动工作流：提示当前已有工作流运行。
- 预设不存在：清除本地选择并刷新预设列表。
- 网络或服务错误：提示 `开始工作流失败`。

## 10. 后端设计

新增按预设启动接口：

`POST /todo/focus/workflows/{preset_id}/start`

接口返回 `FocusWorkflowOut`。

后端行为：

- 查询并校验预设所有权。
- 如果已有活动工作流，返回 `409`。
- 规范化预设阶段。
- 按第一阶段类型初始化运行态。
- 如果第一阶段是未绑定任务的专注阶段，进入 `pending_task_selection`。
- 如果第一阶段已绑定任务，启动对应任务专注日志与专注工作。
- 如果第一阶段是休息阶段，进入休息阶段。

该接口不修改预设本身，也不修改默认工作流标记。

## 11. 测试计划

### 11.1 前端测试

覆盖 `PlaceholderCard` 工作流入口：

- 有上次选择时，入口副文案显示该工作流名称。
- 没有上次选择时，回退显示默认工作流。
- 点击 `开始工作流` 调用 `POST /todo/focus/workflows/{id}/start`。
- 点击工作流名称只打开选择面板，不启动。
- 在选择面板点击预设后更新当前选择并关闭面板。
- 点击 `新建工作流` 打开现有工作流预设管理面板。
- 没有预设时，主入口点击打开工作流预设管理面板。

### 11.2 后端测试

覆盖按预设启动接口：

- 启动当前用户拥有的预设。
- 不能启动其他用户的预设。
- 已有活动工作流时返回冲突。
- 未绑定任务的首个专注阶段进入 `pending_task_selection`。
- 已绑定任务的首个专注阶段进入 `focus` 并带上任务上下文。

### 11.3 浏览器验收

在真实页面验证：

- 主页面显示 `开始工作流`。
- 副文案显示当前选择的工作流名称。
- 点击副文案可切换工作流。
- 切换后刷新页面仍保留上次选择。
- 点击 `开始工作流` 后顶部胶囊进入对应运行态。
- 未绑定任务的工作流启动后进入 `选择任务` 状态。

## 12. 非目标

- 不重做工作流预设管理面板。
- 不把任务选择塞进开始工作流面板。
- 不修改 Vocab/ERC 的专注入口文案。
- 不改变暂停、继续、完成本轮、完成任务并结束专注、放弃本阶段的既有语义。
- 不把当前选择同步成后端默认工作流。
