# ERC 配置收束设计

## 背景

本文记录阅读训练子应用的配置收束设计。这里讨论的是产品和业务规则，不涉及具体代码实现。

当前阅读训练已经具备两个成熟的执行方向：

- 真题练习
- 错题复习

它们都属于同一个子应用：阅读训练。按照 Ark 子应用共性模型，一个事件下每个子应用默认只有一份子应用配置。因此，阅读训练不应被理解成两份彼此独立的应用配置，而应被理解成一份 ERC 应用配置派生出两个可执行模块。

## 核心模型

ERC 在事件下的业务关系应收束为：

```text
事件
  -> ERC 应用配置
    -> 真题练习模块
      -> 真题练习任务
      -> 真题练习专注工作
    -> 错题复习模块
      -> 错题复习任务
      -> 错题复习专注工作
```

业务含义：

- ERC 只有一份绑定事件的应用配置。
- 真题练习和错题复习是这份配置下的两个执行模块。
- 两个模块可以分别派生任务，分别绑定专注工作。
- 两个模块的完成状态彼此独立。
- 两个模块共享同一个 ERC 子应用身份、事件归属和配置入口。

## ERC 应用配置

ERC 应用配置定义阅读训练在某个事件中的目标、范围、节奏和执行模块。

配置应包含两个模块区域：

### 真题练习模块

真题练习模块用于整篇阅读训练。

它应包含：

- 是否启用。
- 每日或每周期文章目标。
- 默认专注时长。
- 是否同步到今日计划。
- 题库或文章范围。
- 执行入口展示规则。

启用后，它派生：

- 真题练习任务。
- 真题练习专注工作。

### 错题复习模块

错题复习模块用于复习题目、错题或到期复习卡。

它应包含：

- 是否启用。
- 复习范围，例如到期题、错题或全部题。
- 每日或每周期题量目标。
- 默认专注时长。
- 是否同步到今日计划。
- 执行入口展示规则。

启用后，它派生：

- 错题复习任务。
- 错题复习专注工作。

## 默认启用策略

默认建议同时启用真题练习和错题复习，因为阅读训练的完整闭环是：

```text
整篇练习
  -> 结果反馈
  -> 错题沉淀
  -> 后续复习
```

但用户可以只启用其中一个模块：

- 只启用真题练习：适合刚开始刷题、还没有错题池或复习池的阶段。
- 只启用错题复习：适合阶段性回顾、冲刺复盘或短时间查漏补缺。

## 模块启用

模块启用时，系统应根据 ERC 应用配置派生或恢复对应任务，并绑定对应专注工作。

```text
启用真题练习模块
  -> 显示真题练习入口
  -> 派生或恢复真题练习任务
  -> 绑定真题练习专注工作

启用错题复习模块
  -> 显示错题复习入口
  -> 派生或恢复错题复习任务
  -> 绑定错题复习专注工作
```

启用后的任务应进入该事件下的应用安排体系。若用户选择同步到今日计划，则对应任务也应进入今日计划。

## 模块停用

模块停用不是删除。

停用某个模块时，应执行以下业务语义：

- 不再显示该模块的执行入口。
- 不再加入今日计划。
- 不再参与当前事件的待执行安排。
- 保留历史任务。
- 保留专注记录。
- 保留任务完成记录。
- 保留 ERC 业务数据，例如练习记录、错题、复习卡、复习日志。

这样可以避免用户因为临时关闭模块而丢失长期记录。

## 重新启用

重新启用模块时，应恢复原任务，而不是创建一个全新任务。

```text
重新启用模块
  -> 恢复原任务
  -> 按当前 ERC 配置同步目标、节奏、专注时长和今日计划状态
  -> 重新显示执行入口
```

恢复原任务的好处是：

- 历史完成记录保持连续。
- 专注记录保持连续。
- 事件进度和成就统计不会被切断。
- 用户能理解这是同一个训练模块的继续，而不是一个新任务。

## 完成状态

两个模块同属一份 ERC 应用配置，但任务完成状态独立。

```text
真题练习今天完成 ≠ 错题复习今天完成
错题复习今天完成 ≠ 真题练习今天完成
```

例如：

- 用户今天提交了一篇真题练习，真题练习任务可以完成。
- 用户没有完成错题复习题量，错题复习任务仍未完成。

反过来也成立。

## 配置入口

事件工作台和 ERC 首页都是同一份 ERC 应用配置的编辑入口。

```text
事件工作台修改 ERC 配置
ERC 首页修改 ERC 配置
  -> 更新同一份事件 ERC 应用配置
  -> 同步真题练习模块
  -> 同步错题复习模块
```

用户不应感知到两套配置。无论从哪个入口修改，都应得到一致结果。

## 配置变更同步规则

修改 ERC 应用配置后，应同步两个模块及其派生任务。

同步规则如下：

1. 保存 ERC 配置后，先校验配置是否有效。
2. 对已启用模块，派生或恢复对应任务。
3. 对已启用模块，同步系统生成字段，例如目标、节奏、默认专注时长、是否进入今日计划。
4. 对已停用模块，隐藏执行入口，并使其不再进入今日计划和待执行安排。
5. 如果任务曾被用户手动调整，不应静默覆盖用户修改。
6. 当配置和已生成任务存在差异时，应保留用户修改，或提示用户处理差异。

## 页面呈现原则

ERC 首页应呈现为一个“阅读训练”子应用，而不是两个彼此割裂的应用。

页面可以展示：

- 一份阅读训练配置摘要。
- 真题练习模块卡片。
- 错题复习模块卡片。
- 两个模块各自的状态和执行入口。
- 当前事件下 ERC 的整体进度摘要。

执行入口应清楚区分：

- 开始真题练习。
- 开始复习。

但配置归属应统一：

> 这两个入口都来自同一份 ERC 应用配置。

## 设计结论

ERC 配置收束后的业务模型是：

1. 一个事件下只有一份 ERC 应用配置。
2. ERC 应用配置包含真题练习和错题复习两个模块。
3. 每个模块可以独立启用或停用。
4. 每个启用模块派生一个任务，并绑定一个专注工作。
5. 停用模块不删除历史，只隐藏入口并停止参与当前安排。
6. 重新启用模块时恢复原任务，而不是创建新任务。
7. 两个模块共享配置入口，但完成状态独立。
8. 事件工作台和 ERC 首页编辑的是同一份配置。

这套设计让 ERC 符合 Ark 子应用共性模型，同时保留阅读训练自身的双模块业务特点。
