## 1. 产品目标

### 1.1 核心目标

将 Ark 当前多种专注工作题型的取题逻辑，收敛为一套统一的取题模型。

### 1.2 统一范围

本规格定义的"统一"，是指取题逻辑的统一，而非题目呈现样式的统一。具体而言：

| 维度 | 是否统一 | 说明 |
|---|---|---|
| 取题流程 | 统一 | 所有题型共用同一套取题流程 |
| 筛选规则 | 统一 | 所有题型共用同一套筛选条件体系 |
| 学习档案 | 统一 | 所有题型共用同一套学习档案概念 |
| 作答记录 | 统一 | 所有题型共用同一套作答记录概念 |
| 专注工作配置 | 统一 | 所有题型共用同一套配置模型 |
| 内容展示方式 | 不统一 | 各题型可独立设计展示样式 |
| 作答判定方式 | 不统一 | 各题型可独立定义判定逻辑 |

### 1.3 非目标

- 本轮不讨论统一题库字段规范。
- 本轮不产出技术实现方案。
- 本轮不改变各题型的内容展示与作答判定方式。

## 2. 设计原则

### 2.1 配置驱动

用户通过专注工作配置控制本次练题的范围、顺序、数量与回流行为。系统严格按配置执行，不做未声明的"智能调整"。

### 2.2 严格模式

系统默认采用严格模式：条件不足时如实告知用户，不自动放宽条件、不自动补题。

### 2.3 学习档案与作答记录分离

- **学习档案**：描述用户对某题的当前学习状态，是"此刻的快照"。
- **作答记录**：描述用户某次作答的客观事实，是"历史的流水"。

二者职责不同，不可互相替代。

### 2.4 调度与回流分离

- **学习调度**：回答"以后什么时候再练这题"，由 FSRS 负责。
- **本场回流**：回答"这场专注里要不要马上再练一次"，由回流规则负责。

二者机制独立，不可混为一谈。

### 2.5 FSRS 可选

FSRS 是可选的学习调度机制。未启用 FSRS 时，系统仍可完整运行所有练题功能。启用 FSRS 时，系统额外提供到期复习等调度型玩法。

### 2.6 配置影响范围明确

编辑专注工作配置只影响未来启动的专注工作，不影响已开始的专注、历史记录与历史结算。

## 3. 核心业务对象定义

### 3.1 题库

题库是静态题目的集合。每个题目至少包含：序号、材料、题目、答案、解析、标签信息。

> 本轮不展开统一题库字段规范。

### 3.2 学习档案

学习档案由"用户 + 具体题目"唯一确定，表示该用户对该题的当前学习状态。

学习档案承载以下信息：

**基础信息**（始终维护）：

| 信息项 | 业务含义 |
|---|---|
| 做题次数 | 该用户一共做过这道题多少次 |
| 上次做题时间 | 最近一次作答的时间 |
| 上次耗时 | 最近一次作答所花费的时间 |
| 上次结果 | 最近一次作答的结果（正确/错误） |
| 累计错误次数 | 该用户做这道题一共错了几次 |

**调度信息**（始终保留，仅在启用 FSRS 时更新和使用）：

| 信息项 | 业务含义 |
|---|---|
| 下次复习时间 | 建议下一次复习此题的时间点 |
| 调度状态 | 当前在调度模型中的状态 |
| 调度参数 | FSRS 模型所需的内部参数 |

### 3.3 作答记录

作答记录由"用户 + 题目 + 作答时间"确定，每次作答产生一条，是历史事实的不可变记录。

作答记录至少包含：
- 作答了哪道题
- 作答发生在哪次专注工作中
- 作答结果（正确/错误）
- 作答耗时
- 是否是本场回流题
- 作答时间

### 3.4 专注工作配置

专注工作配置定义了一次专注工作如何取题、如何运行。

## 4. 专注工作配置项定义

### 4.1 配置项列表

| 配置项 | 业务含义 | 可选值 | 默认值 |
|---|---|---|---|
| 所属题库 | 从哪个题库中取题 | 用户可访问的题库列表 | 必选，无默认值 |
| 目标题量 | 本次专注预计做多少题 | 正整数 | 20 |
| 主筛选条件 | 按什么状态筛选题目 | 见第 5 章 | 全部题目 |
| 标签过滤 | 在筛选结果上叠加标签条件 | 见第 6 章 | 不过滤 |
| 排序方式 | 题目以什么顺序出现 | 见第 7 章 | 按序号 |
| 启用 FSRS | 是否启用 FSRS 学习调度 | 是/否 | 否 |
| 本场回流方式 | 做错的题是否再次出现 | 见第 12 章 | 不回流 |

### 4.2 配置校验规则

- 所属题库为必选项。
- 目标题量必须为正整数。
- 若启用"到期复习"主筛选条件，必须同时启用 FSRS。
- 编辑已有配置与新建配置遵守相同的校验规则。

## 5. 主筛选条件规则

### 5.1 设计决策：主筛选条件为单选

**结论：主筛选条件为互斥单选。**

理由：

1. **用户心智清晰**：用户一次只需要做一个选择——"我这次想练什么样的题"。单选避免用户陷入"同时选了做错过和没做过，到底怎么算"的困惑。
2. **规则确定性**：互斥条件使得系统行为完全可预期，不存在多条件交叉后的歧义。
3. **产品复杂度可控**：如果允许多选，需要在并列/交集/并集之间做出选择，且每种组合的语义都需要单独定义，大幅增加理解成本和评审风险。
4. **标签过滤承担叠加职责**：需要叠加条件时，通过标签过滤实现，不必让主筛选条件承担叠加责任。

### 5.2 主筛选条件选项定义

#### 5.2.1 全部题目

- **业务含义**：不做学习状态上的筛选，题库中所有题目均参与本次取题。
- **适用场景**：用户想无差别练习、首次接触题库、或希望覆盖所有题目。

#### 5.2.2 没做过

- **业务含义**：筛选出该用户从未做过的题目。
- **判定规则**：以学习档案是否存在为准。若某题不存在于该用户的学习档案中，即为"没做过"。
- **边界情况**：若用户从未在任何一次专注中答过此题，即视为"没做过"。

#### 5.2.3 做错过

- **业务含义**：筛选出该用户历史上至少做错过一次的题目。
- **判定规则**：以学习档案中的"累计错误次数"为准。累计错误次数 ≥ 1 即为"做错过"。
- **注意**：做错过 ≠ 上次做错。做错过是历史维度，上次做错是最近一次维度。

#### 5.2.4 上次做错

- **业务含义**：筛选出该用户最近一次作答结果为错误的题目。
- **判定规则**：以学习档案中的"上次结果"为准。上次结果为"错误"即为"上次做错"。
- **与"做错过"的区别**：
  - 做错过：历史上错过，最近一次可能对也可能错。
  - 上次做错：最近一次是错的，历史上可能对过。

#### 5.2.5 到期复习

- **业务含义**：筛选出"下次复习时间"不晚于当前时间的题目，即当前处于待复习状态的题目。
- **前置条件**：必须启用 FSRS。若未启用 FSRS，此选项不可见或置灰。
- **判定规则**：以学习档案中的"下次复习时间"为准。下次复习时间 ≤ 当前时间即为到期。
- **适用场景**：用户希望按 FSRS 计划进行周期性复习，只练到期的题目。

### 5.3 主筛选条件小结

| 主筛选条件 | 判定依据 | 前置条件 |
|---|---|---|
| 全部题目 | 无 | 无 |
| 没做过 | 学习档案是否存在 | 无 |
| 做错过 | 累计错误次数 ≥ 1 | 无 |
| 上次做错 | 上次结果 = 错误 | 无 |
| 到期复习 | 下次复习时间 ≤ 当前时间 | 必须启用 FSRS |

## 6. 标签过滤规则

### 6.1 业务定位

标签过滤是叠加条件，不是主决策维度。用户在主筛选条件选定的题目范围内，通过标签进一步缩小范围。

### 6.2 组合方式

标签过滤与主筛选条件之间为"交集"关系：

> 最终题单 = 满足主筛选条件的题目 ∩ 满足标签过滤条件的题目

### 6.3 标签维度

标签按业务语义划分为以下维度：

| 维度 | 业务含义 | 使用方式 |
|---|---|---|
| 年份 | 题目所属年份（如 2024、2025） | 可多选 |
| 科目 | 题目所属科目（如语文、数学、英语） | 可多选 |
| 类型 | 题目类型（如选择题、填空题、阅读理解） | 可多选 |
| 自定义标签 | 用户或管理员自定义的标签 | 可多选 |

同一维度内多个标签为"或"关系。不同维度之间为"且"关系。

示例：
- 年份选了 [2024, 2025]，科目选了 [数学]，则筛选"2024或2025年的数学题"。
- 年份不选，科目选了 [语文]，则筛选"所有年份的语文题"。

### 6.4 无筛选时的行为

当用户未选择任何标签过滤条件时，标签过滤不生效，所有满足主筛选条件的题目均参与取题。

## 7. 排序规则

### 7.1 排序方式定义

#### 7.1.1 按序号

- **业务含义**：按题目在题库中的原始序号升序排列。
- **是否依赖 FSRS**：否。
- **适用场景**：用户希望按题库编排顺序依次练习。

#### 7.1.2 按到期时间

- **业务含义**：按"下次复习时间"升序排列，到期时间越早的题越靠前。没有调度信息的题排在有调度信息的题之后。
- **是否依赖 FSRS**：是。未启用 FSRS 时此选项不可见或置灰。
- **适用场景**：用户在做"到期复习"时希望优先练最该复习的题。

#### 7.1.3 按错误优先

- **业务含义**：错误次数越多的题越靠前。错误次数相同时，按序号排列。
- **是否依赖 FSRS**：否。
- **适用场景**：用户想优先攻克薄弱点。

#### 7.1.4 随机

- **业务含义**：将符合条件的题目随机打乱后排列。
- **是否依赖 FSRS**：否。
- **适用场景**：用户希望打破固定顺序，增加练习的多样性。

### 7.2 默认排序建议

**默认排序：按序号。**

理由：
1. 按序号是最直观、最无歧义的排序方式。
2. 不依赖任何学习数据，在用户首次使用、无历史数据时也能正常工作。
3. 与"全部题目"默认主筛选条件搭配，形成最简即可上手的体验。

### 7.3 排序方式与 FSRS 的关系

| 排序方式 | 未启用 FSRS | 启用 FSRS |
|---|---|---|
| 按序号 | 可用 | 可用 |
| 按到期时间 | 不可用 | 可用 |
| 按错误优先 | 可用 | 可用 |
| 随机 | 可用 | 可用 |

## 8. 学习档案规则

### 8.1 核心定位

学习档案是"当前状态"，不是历史流水。它回答的问题是："这位用户现在对这道题的掌握情况如何？"

### 8.2 学习状态术语

为统一沟通，定义以下学习状态：

| 状态名称 | 业务含义 | 判定规则 |
|---|---|---|
| 新题 | 用户从未做过此题 | 不存在学习档案 |
| 学习中 | 用户做过此题，但尚未进入稳定复习阶段 | 学习档案存在，做题次数较少（具体阈值可在后续版本中定义，本版本暂不设硬阈值） |
| 复习中 | 用户正在按调度计划复习此题 | 学习档案存在，且调度状态为"复习中" |
| 返工中 | 用户最近一次做错此题，需要重新巩固 | 学习档案存在，且上次结果 = 错误 |

### 8.3 学习档案的更新时机

- **每次作答后立即更新**：无论是否启用 FSRS，作答结束后学习档案立即更新。
- **基础信息始终更新**：做题次数、上次做题时间、上次耗时、上次结果、累计错误次数每次作答后更新。
- **调度信息有条件更新**：仅在启用 FSRS 时，调度信息（下次复习时间、调度状态、调度参数）随作答更新。未启用 FSRS 时，调度信息保留原值不变。

### 8.4 学习档案的创建时机

当用户第一次面对某题并作答后，系统为该用户创建该题的学习档案。在此之前，该题对该用户而言为"新题"。

## 9. 作答记录规则

### 9.1 核心定位

作答记录是"历史事实"，每条记录不可变。它回答的问题是："这位用户在这次专注中，做这道题时发生了什么？"

### 9.2 记录内容

每条作答记录至少包含：
- 所属用户
- 所属题目
- 所属专注工作
- 作答结果（正确/错误）
- 作答耗时
- 是否为本场回流题
- 作答时间

### 9.3 与学习档案的关系

| | 学习档案 | 作答记录 |
|---|---|---|
| 性质 | 当前状态 | 历史事实 |
| 更新方式 | 覆盖更新 | 追加新增 |
| 用途 | 决定取题范围、展示学习状态 | 提供历史回顾、数据统计 |
| 是否可改 | 是（随每次作答更新） | 否（追加，不修改已有记录） |

## 10. FSRS 可选机制的业务定位

### 10.1 FSRS 是什么

FSRS 是一种基于用户作答历史的间隔重复调度算法。其核心功能是：根据用户每次作答的表现，计算下一次复习的最佳时间点。

### 10.2 FSRS 的角色边界

| 角色 | FSRS 负责 | FSRS 不负责 |
|---|---|---|
| 学习调度 | 决定"以后什么时候再练这题" | — |
| 作答结算 | — | 不负责结算、计分、统计 |
| 本场回流 | — | 不负责当前专注内的题目回流 |
| 筛选题库 | 提供"到期复习"筛选依据 | 不负责筛选之外的其他逻辑 |

### 10.3 未启用 FSRS 时的系统行为

- 学习档案的基础信息正常更新。
- 调度信息保留但不更新、不参与取题。
- "到期复习"主筛选条件不可用。
- "按到期时间"排序方式不可用。
- 结算页不展示复习计划更新提示。
- 用户仍然可以正常练题、查看学习档案、查看作答记录。

### 10.4 启用 FSRS 时的系统行为

- 每次作答后，立即将作答结果输入 FSRS 模型，更新学习档案的调度信息。
- "到期复习"主筛选条件可用。
- "按到期时间"排序方式可用。
- 结算页展示复习计划更新提示。

### 10.5 重要强调

> **结算阶段不负责计算调度。** FSRS 的调度计算在每次作答后即时完成，结算阶段只做汇总展示。结算页不会、也不应该触发任何调度计算。

## 11. 统一取题流程

### 11.1 完整流程

以下为一次专注工作的完整业务流程：

#### 阶段一：配置

1. 用户进入专注工作配置界面。
2. 用户选择或确认以下配置项：
   - 所属题库
   - 目标题量
   - 主筛选条件
   - 标签过滤（可选）
   - 排序方式
   - 是否启用 FSRS
   - 本场回流方式
3. 系统执行配置校验（校验规则见 4.2）。
4. 系统计算匹配题量，并在界面上展示：
   - 匹配题量 ≥ 目标题量：提示"共匹配 N 题，本次将抽取目标题量 M 题"。
   - 匹配题量 < 目标题量且 > 0：提示"仅匹配 N 题，不足目标 M 题，将按实际题量开始"。
   - 匹配题量 = 0：提示"当前条件无可选题，请调整配置"，并阻止开始。

#### 阶段二：生成题单

5. 用户确认配置后，点击开始。
6. 系统按配置生成固定题单：
   - 从题库中筛选出满足主筛选条件的题目。
   - 在筛选结果上叠加标签过滤条件。
   - 按指定排序方式排列。
   - 如果匹配题量 ≥ 目标题量，取前目标题量题。
   - 如果匹配题量 < 目标题量，取全部匹配题。
7. 题单一旦生成，即视为固定。本次专注内的题序与题量不再因配置变化、题库变化而改变。

#### 阶段三：逐题作答

8. 用户逐题作答。
9. 每答完一题，系统执行以下动作（同步、即时）：
   a. 生成一条作答记录。
   b. 更新学习档案的基础信息。
   c. 若启用 FSRS，更新学习档案的调度信息。
   d. 若触发本场回流，将该题按回流规则重新加入本次题单末尾。
10. 用户作答完题单中所有题目（含回流新增的题目），或用户主动结束，本次专注进入结算阶段。

#### 阶段四：结算

11. 系统汇总本次专注的作答记录，生成结算展示内容（详见第 13 章）。
12. 结算阶段不做任何调度计算。

### 11.2 关键规则

- **题单固定原则**：专注一旦开始，题单视为固定。用户中途修改配置不影响当前专注，只影响下一次启动的专注。
- **即时更新原则**：每道题的作答结果在作答完成后立即写入作答记录和学习档案，不等到结算时才批量处理。

## 12. 本场回流规则

### 12.1 什么是本场回流

本场回流是指：在本次专注工作中，当用户答错某道题时，系统将该题重新加入本次题单末尾，让用户在当前场次内再次作答。

### 12.2 本场回流与 FSRS 的关系

本场回流与 FSRS 是两套独立机制：

| | 本场回流 | FSRS |
|---|---|---|
| 作用域 | 当前场次内 | 跨场次的长期调度 |
| 触发条件 | 答错 | 每次作答（无论对错） |
| 是否可选 | 是（由回流方式配置控制） | 是（由 FSRS 开关控制） |
| 对学习档案的影响 | 不直接影响调度信息 | 直接影响调度信息 |

> 本场回流不属于 FSRS 本体，也不依赖 FSRS。未启用 FSRS 时，本场回流仍然可以独立生效。

### 12.3 回流方式选项

| 回流方式 | 行为描述 |
|---|---|
| 不回流 | 答错的题不再次出现。用户做完题单即结束本次专注。 |
| 答错放队尾 | 答错的题追加到题单末尾。用户需要将追加的题也做完才能结束本次专注。 |
| 答错立即再来一次 | 答错的题立即再次呈现（插在当前题之后）。 |

### 12.4 推荐默认回流方式

**推荐默认值：不回流。**

理由：
1. **降低用户心智负担**：回流会增加本次专注的不确定性和时长，不适合作为默认体验。
2. **符合"一次专注完成一个固定题单"的直觉**：默认不回流让用户清楚知道"做完 N 题就结束"。
3. **与严格模式一脉相承**：默认严格执行用户配置，不做隐含的追加行为。
4. 需要回流的用户可以通过配置显式开启，不会丢失功能。

### 12.5 回流规则细则

#### 同一题重复回流

如果同一题被追加到队尾后再次答错，是否继续回流？

**规则：同一题在同一场专注中最多回流一次。** 即一道题在本次专注中最常出现两次（首次 + 一次回流）。避免某一题无限循环，影响用户体验。

#### 回流题是否计入本次总题量

回流题不计入目标题量，只计入实际做题量。结算时区分展示"目标题量"与"实际做题量（含回流）"。

#### 回流题是否影响结算展示

回流题在结算中需要特殊标注，让用户知道哪些题是回流题。详情见第 13 章。

## 13. 结算阶段展示规则

### 13.1 结算页定位

**结算页的定位是"成绩单 + 复盘页 + 学习状态变化页"三位一体。** 它在一次专注结束后，同时承载三个目的：

1. 告知用户本次练得怎么样（成绩单）。
2. 让用户回顾答错和回流的内容（复盘）。
3. 让用户知道哪些题的学习状态发生了变化（学习状态变化）。

### 13.2 展示层级

#### 第一层：摘要层

| 展示项 | 说明 |
|---|---|
| 实际做题数量 | 本次专注实际作答的题数（含回流题） |
| 目标题量 | 本次专注配置的目标题量 |
| 正确数量 | 答对的题数 |
| 错误数量 | 答错的题数 |
| 总用时 | 本次专注累计用时 |
| 是否完成目标 | 实际做题数量 ≥ 目标题量即为完成 |

#### 第二层：结果层

展示本次专注中每道题的作答情况：

| 展示项 | 说明 |
|---|---|
| 题目列表 | 按作答顺序展示每道题 |
| 作答结果 | 标注正确/错误 |
| 回流标识 | 标注该题是否为本场回流题 |

建议以列表形式展示，每道题至少展示：
- 题目标题或序号
- 作答结果（正确/错误）
- 是否为回流题
- 作答耗时

#### 第三层：学习变化层

展示本次专注后学习状态发生变化的题目：

| 展示项 | 说明 |
|---|---|
| 新掌握 | 首次答对的题目（从"新题"进入"学习中"） |
| 需巩固 | 最近一次答错的题目（进入"返工中"） |
| 需复习 | 若启用 FSRS，已安排下次复习的题目 |

#### 第四层：调度提示层

- **若启用 FSRS**：提示"复习计划已更新"，可简要告知用户下一轮到期复习的题目数量。
- **若未启用 FSRS**：提示"本次练习结果已记录，如需基于本次结果安排复习计划，请开启 FSRS"。

### 13.3 本次学习记录的展示粒度

结算页应展示"本次学习记录"，粒度如下：
- 每道题单独一条作答记录。
- 用户可逐题回顾自己的作答结果。
- 回流题明确标注，便于用户理解为什么会多做题。

## 14. 编辑已有专注工作配置规则

### 14.1 统一模型原则

编辑已有专注工作配置与新建专注工作配置，使用完全相同的统一取题模型。具体而言：

| 维度 | 新建配置 | 编辑已有配置 |
|---|---|---|
| 配置项 | 完整 | 完整（与新建相同） |
| 校验规则 | 完整 | 完整（与新建相同） |
| 默认值 | 完整 | 保留当前值，用户可修改 |
| 取题流程 | 统一流程 | 统一流程 |

### 14.2 影响范围

编辑配置保存后：
- **影响**：未来启动的专注工作。
- **不影响**：已经开始的专注工作。
- **不影响**：历史作答记录。
- **不影响**：历史学习档案。
- **不影响**：历史结算结果。

### 14.3 旧配置兼容说明

如果系统中存在旧版本创建的专注工作配置（即在新模型上线前创建的配置），在编辑时需要按新模型重新解释其配置项：

| 旧配置可能的情况 | 编辑时的处理方式 |
|---|---|
| 旧配置中缺少新模型新增的配置项 | 使用新模型的默认值填充 |
| 旧配置中存在新模型中已废弃的配置项 | 编辑时不再展示，保存时丢弃 |
| 旧配置中的值与新模型语义一致 | 直接继承当前值 |

如果存在旧配置中的某个值无法无歧义地映射为新模型中的配置项，此类情况将列入"待确认事项"（见第 18 章）。

## 15. 边界情况处理规则

### 15.1 题量不足

- **匹配题量 ≥ 目标题量**：正常开始，抽取目标题量题目。
- **0 < 匹配题量 < 目标题量**：按实际匹配题量开始，并在开始前明确提示用户"当前条件仅匹配 N 题，不足目标 M 题，将按实际题量开始"。用户确认后开始。
- **匹配题量 = 0**：不允许开始。界面上提示"当前条件无可选题，请调整筛选条件或标签过滤"，引导用户修改配置。
- **在任何情况下，系统不自动放宽筛选条件、不自动补入不满足条件的题。**

### 15.2 当前条件下没有可用题

即匹配题量 = 0。处理方式同上条。系统引导用户调整配置，不提供任何自动替代方案。

### 15.3 用户中途退出

- 用户主动退出专注时，已产生的作答记录保留，不删除。
- 已更新的学习档案保留，不回滚。
- 未作答的题目不作任何记录。
- 本次专注标记为"未完成"或"中途退出"，不进入完整结算流程。但用户仍可查看已作答部分的摘要信息。

### 15.4 用户暂停后恢复

- 暂停期间，题单保持不变。
- 恢复后，从暂停时的题目继续。
- 暂停期间的配置变化不影响本次题单。

### 15.5 题库在专注进行中发生变化

- **题目内容修改**：如果题单中的某题内容被修改，本次专注仍使用开始时的题目快照（即修改不影响当前专注）。
- **题目被删除**：如果题单中的某题被删除，该题在题单中标记为"不可用"，跳过该题。实际题量相应减少。
- **新增题目**：本次题单固定，新增题目不进入本次专注。

### 15.6 同一题因回流再次出现

- 同一题在同一场专注中最常出现两次（首次 + 一次回流）。
- 回流出现的题目，作答记录中标记为"回流题"。
- 回流题的学习档案更新规则与首次作答相同（基础信息更新、调度信息条件更新）。

### 15.7 用户编辑配置后重新启动下一次专注

- 编辑后的配置在下一次启动专注时生效。
- 前一次专注产生的作答记录、学习档案信息正常影响下一次取题（如"上次做错"、"做错过"等筛选条件会基于最新学习档案）。

### 15.8 未启用 FSRS 时用户仍有历史调度信息

可能的场景：用户之前启用了 FSRS，后来关闭了 FSRS。此时学习档案中仍有历史调度信息。

- 历史调度信息保留不丢失。
- 未启用 FSRS 时，调度信息不参与本次取题（"到期复习"和"按到期时间"不可用）。
- 如果用户后续重新启用 FSRS，历史调度信息仍然有效，可被"到期复习"筛选和"按到期时间"排序使用。

### 15.9 启用 FSRS 时用户历史上从未做过任何题

- 所有题目的学习档案均不存在，均为"新题"。
- "到期复习"主筛选条件下的匹配题量 = 0（因为没有题目有调度信息）。
- "按到期时间"排序下所有题目无调度信息，排在后面，按默认序号排列。

## 17. 用户心智说明

### 17.1 核心心智模型

用户使用统一取题模型时，心智模型是：

> "我选择一批题目，按某种顺序，做完它们，看看做得怎么样。"

这个心智模型可以拆解为四个阶段：

1. **选范围**（主筛选 + 标签过滤）：我这次想做什么范围的题？
2. **定顺序**（排序方式）：我想按什么顺序做？
3. **做题**（逐题作答）：一题一题认真做。
4. **看结果**（结算）：我做得怎么样？哪些题还需要再练？

### 17.2 FSRS 的心智定位

FSRS 在用户心智中是"增值功能"而非"基础功能"：

- 用户不需要 FSRS 就能完整使用练题功能。
- FSRS 解决的是"我该什么时候再练"的问题，而不是"我现在怎么练"的问题。
- 用户决定开启 FSRS，意味着用户想要系统帮TA管理复习节奏。

### 17.3 本场回流的心智定位

本场回流在用户心智中是"惩罚/巩固机制"：

- 不回流 = 做完就走，错题下次再说。
- 答错放队尾 = 错了必须当场再做一次才能结束。
- 答错立即再来一次 = 错了马上重新挑战。

用户可以根据自己的学习习惯和场景选择合适的回流方式。

### 17.4 严格模式的心智定位

严格模式传达给用户的心智是：

> "系统不会替我做决定。条件不够时，系统告诉我实情，我来决定怎么做。"

这建立了用户对系统的信任感，避免系统"自作聪明"导致用户困惑。
