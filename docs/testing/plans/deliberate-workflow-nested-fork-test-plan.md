## 1. 功能概述

本方案用于验证「刻意学习流」中专注工作 Fork 到另一个专注工作后的嵌套结算语义。当前测试数据中，基础编排为：

```text
英语阅读选择 -> 408选择
```

其中：

```text
英语阅读选择 fork 到 闪卡
408选择 fork 到 408选择2
```

因此，一个完整的嵌套 Fork 工作流应展开为：

```text
英语阅读选择 -> 闪卡 -> 英语阅读选择 -> 408选择 -> 408选择2 -> 408选择
```

这里的重复父节点不是重新开始一个普通阶段，而是「子专注工作完成后回到父专注工作的结算上下文」。只有父节点最终确认完成后，工作流才进入下一个平级专注工作。

**核心能力：**
- 父专注工作未通过结算时展示配置好的 Fork 子节点。
- Fork 子专注工作完成后回到父专注工作的结算上下文。
- 父专注工作最终确认完成后，才进入下一个平级专注工作。
- 同一个组合工作流中可连续验证两组 Fork：`英语阅读选择 -> 闪卡 -> 英语阅读选择` 与 `408选择 -> 408选择2 -> 408选择`。
- 运行档案可追踪父 run、子 run、source_run_id 和组合工作流节点关系。

### P0 - 核心功能

#### 场景 S01：确认测试数据和 Fork 关系

**优先级：** P0  
**前置条件：** 后端和前端服务已启动，测试账号可登录。

**操作步骤：**

```text
1. browser_navigate: 访问 http://localhost:5173/#/deliberate-workflow
2. browser_snapshot: 确认页面加载完成并显示「专注工作管理」
3. browser_snapshot: 确认专注工作列表包含四个配置
4. browser_click: 点击 `英语阅读选择` 的编辑按钮
5. browser_snapshot: 确认子节点（fork 目标）包含 `闪卡`
6. browser_click: 关闭弹窗
7. browser_click: 点击 `408选择` 的编辑按钮
8. browser_snapshot: 确认子节点（fork 目标）包含 `408选择2`
9. browser_click: 关闭弹窗
```

**预期结果：**
- 四个测试专注工作均存在。
- `英语阅读选择` 配置了 Fork 子节点 `闪卡`。
- `408选择` 配置了 Fork 子节点 `408选择2`。
- 两个父专注工作均启用了可触发未通过的通过标准。

**验证方法：**
- 前端编辑弹窗视觉验证。
- （仅前端验证，跳过 API 验证）：请求 `/api/admin/deliberate-workflows/{config_id}`，检查 `children` 和 `pass_criteria`。
