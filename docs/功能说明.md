# Ark 功能说明

> 本文档为 Ark 项目的正式功能说明，面向用户介绍各核心模块的设计理念、功能边界与使用方法。

---

## 一、事件（Event）

### 1.1 设计理念

"事件"是 Ark 中最上层的组织单元。当你即将面临一个人生中的重要阶段——一场考试、一个项目截止日、一次比赛——你便处于一个"事件"当中。事件为你提供了一个时间边界，让你在有始有终的框架内规划和推进所有相关事宜。

每一个事件都有**开始日期**（`start_date`）与**截止日期**（`due_at`），这段时间将成为你人生中一段不可磨灭的记录。

### 1.2 功能概述

| 能力 | 说明 |
|---|---|
| 创建事件 | 设定事件名称、开始日期与截止日期 |
| 设为主事件 | 同一时间仅有一个主事件，主事件将展示在主界面的倒计时中 |
| 编辑事件 | 修改事件信息，截止日期的变更将自动联动到关联的任务与日程 |
| 删除事件 | 移除不再需要的事件 |
| 事件工作台 | 为事件生成规划草案，拆解"安排" |

### 1.3 事件工作台（Event Workbench）

事件工作台是事件的核心操作面板。进入工作台后，你可以：

- **生成规划草案**：系统根据事件的时间跨度为你的事件自动拆解出一组安排项（任务与日程）。你也可以从模板快速套用预定义的拆解方案。
- **编辑草案项**：对每一项进行调整——修改标题、内容、排定日期等。
- **生成安排**：确认草案后将其转化为正式的任务与日程，后者会自动关联到当前事件。

### 1.4 事件规划模板（Event Plan Template）

如果你有可持续复用的"节奏"（例如每次考试前的复习计划），可以将其保存为**规划模板**。模板定义了若干步骤，每一步以相对天数定位（"从开始日第 N 天"或"距截止日 N 天"），在应用到具体事件时，系统自动计算绝对日期。

模板支持两种排程模式：

- **`from_start`**：从事件的开始日期正向递推
- **`before_due`**：从事件的截止日期反向倒推

### 1.5 使用方法

1. 在右侧面板的"安排"区域创建或管理事件
2. 点击左侧面板的主事件倒计时圆圈进入事件工作台
3. 在工作台中生成/编辑草案，确认后一键生成安排
4. 在模板管理器中维护可复用的规划模板

## 二、安排（Arrangement）：任务与日程

"安排"是事件的子项，分为两类——**任务**与**日程**。如原文所述：如果说任务是你要推动的事情（背完单词书、刷完真题），日程则是你要守住的时间锚点（模考日期、报名截止日）。一个关乎推进，一个关乎节奏。

### 2.1 任务（Task）

任务的本质是**需要持续推进并完成的工作项**。每个任务支持以下配置：

| 属性 | 说明 |
|---|---|
| 标题与内容 | 描述任务的核心信息 |
| 优先级 | 0-3 级，对应不同重要程度 |
| 周期类型 | 一次性（`once`）、每天（`daily`）、每周（`weekly`）、每月（`monthly`）、自定义天数（`custom_days`） |
| 每周期完成上限 | 控制周期内最多完成次数 |
| 仅工作日 | 开启后仅在工作日出现 |
| 目标时长 | 每次专注的预计时长（分钟） |
| 关联事件 | 绑定到特定事件，受事件截止日期联动 |
| 开始/截止日期 | 为任务设定时间边界，在日历视图中以时间条展示 |
| 标签 | 自定义分类标签 |

任务还分为两种类型：

- **专注任务**（`focus`）：需要进行深度工作的任务，可通过专注计时器来完成
- **打卡任务**（`checkin`）：快速确认即可完成的事项（如"吃药"、"做拉伸"）

任务的完成状态通过周期追踪系统动态计算：对于循环任务，系统会判断当前周期内是否已完成、是否达到了完成上限。

### 2.2 日程（Appointment）

日程代表有明确时间点的安排，如课程、会议、模考等。其特殊属性：

| 属性 | 说明 |
|---|---|
| 开始/结束时间 | 精确到分钟的时间段 |
| 状态 | 待确认 → 已出席 / 已错过 / 已取消 |
| 重复规则 | 支持周期性重复 |
| 关联任务 | 可将日程链接到一个任务（如"模考"日程链接到"模考分析"任务） |

### 2.3 使用方法

1. 在右侧面板底部"创建安排"区域，切换到"任务"或"日程"标签页
2. 填写相关信息后创建
3. 创建时可选择关联事件，使安排纳入事件的整体规划
4. 在列表中直接完成/确认安排项
5. 可借助 AI 助手（任务助手）通过自然语言描述批量生成安排

## 三、工作流（Workflow）

### 3.1 设计理念

工作流是单次专注中的**最小粒度**。它把不同类型的任务——每日任务、每周任务、自定义任务、子应用任务——通过预设的顺序编排在一起，然后用"专注-休息-专注"的循环去完成。

简而言之：**工作流定义了"怎么做"的节奏。**

### 3.2 预设（Preset）

工作流预设是一套可复用的阶段序列：

- 每个阶段可以是**专注阶段**（`focus`）或**休息阶段**（`break`）
- 每个阶段可设置时长（以秒为单位）和计时模式（倒计时 / 正计时）
- 专注阶段可绑定具体任务 ID 或指定专注工作类型（如背单词、做阅读）
- 可设置默认预设，系统将优先选用

系统提供默认的 25 分钟专注 + 5 分钟休息模板，你可以在此基础上修改，或创建全新的预设。

### 3.3 运行机制

启动工作流后，系统进入循环：

1. 进入**专注阶段** → 开启全屏工作台（如配置了专注工作类型）
2. 阶段结束后 → 等待用户**确认**（`pending_confirmation`）
3. 进入**休息阶段** → 计时结束后提示
4. 回到步骤 1，开始下一个专注阶段
5. 所有阶段完成后 → 工作流结束，恢复普通状态

支持暂停（`pause`）、恢复（`resume`）、跳过当前阶段（`skip_phase`）等操作。

### 3.4 使用方法

1. 在右侧面板的"工作流"区域查看当前状态
2. 在"工作流预设"区域创建/编辑预设
3. 选定预设后，启动工作流进入专注循环
4. 顶部导航栏的进度条可随时查看当前工作流进度

## 四、专注工作（Focus Work）

### 4.1 设计理念

> 为什么会设计成全屏的、不可退出的工作台？因为深度工作的最大敌人是切换。当你打开工作台，你等于在跟自己签一份短约：接下来的这段时间，我只看这一件事。切出去看消息、刷社交网络的成本被刻意提高了——不是不能，而是需要你主动放弃这次专注。这个摩擦力本身就是设计的一部分。

专注工作是 Ark 的核心体验。它是一个**全屏的、有退出成本**的工作环境，确保你在专注期间不被轻易打断。

### 4.2 专注工作类型

系统目前支持三种专注工作类型：

| 类型 | 标识 | 说明 |
|---|---|---|
| 任务专注 | `task_focus` | 针对用户自建任务的深度工作，支持计时追踪 |
| 今日单词 | `vocab_today` | 当日词汇学习计划，集成 SRS 间隔重复系统 |
| 阅读理解 | `erc_review` | 英语阅读理解复习，集成 FSRS 间隔重复 |

### 4.3 生命周期

专注工作的完整生命周期：

1. **启动**：通过任务上的"开始专注"按钮或应用内的触发点发起
2. **记录确认**：系统询问"记录这次专注吗？"——选择记录则追踪时长与成果
3. **全屏专注**：进入全屏工作台，展示对应类型的内容界面，无法切换到应用其他部分
4. **操作**：支持暂停、恢复、放弃当前专注
5. **结束**：完成后提交结果（`completed` / `interrupted` / `abandoned`），系统记录本次专注日志

### 4.4 使用方法

1. 从任务列表或应用页面的"开始专注"按钮启动
2. 选择是否记录此次专注
3. 在全屏工作台中完成对应内容
4. 完成后提交结果，系统自动记录专注数据

## 五、成就（Achievement）

### 5.1 设计理念

> 事件的持续时间很长，长到会让你感到无所适从，因此引入了"成就"来为你的专注更有反馈。你的每一步努力都会被"成就"所记录，并在合适的时机跳出来为你喝彩。
>
> 成就不是游戏化的虚荣指标。它不要求你做额外的动作，不需要你去打卡领取。你只管做事，成就会自己找上门——完成第一项安排、累计专注两小时、连续三天都在推进事件……系统只是在确认一个事实：你确实在往前走。当你在事件的漫长时间线里感到迷茫时，这些小小的里程碑会提醒你，你已经走了多远。

### 5.2 成就体系

成就分为两个层级：

**事件成就**（Event Achievements）——关联到当前主事件：
- 事件截止前夕完成
- 事件期间累计专注分钟数
- 事件下已确认的日程数量
- 完成事件下第一项安排
- 连续推动事件的次数

**全局成就**（Global Achievements）——跨越事件，累积记录：
- 累计专注天数
- 最长连续专注天数
- 累计完成任务/日程总数
- 掌握的单词数量

### 5.3 展示方式

- **卡片预览**：右侧面板的成就卡片在悬停时显示已解锁与即将解锁的成就
- **弹窗详情**：点击卡片进入成就总览弹窗，按事件/全局分类查看
- **进度条**：每项成就展示当前值与目标值的进度
- **事件切换器**：可在弹窗中切换不同事件，查看各自的事件成就

### 5.4 使用方法

成就系统无需主动操作。你的每一次专注、每一项完成、每一天的推进都会被系统自动追踪。你只需在成就面板中查看进展——它们会在合适的时机自己跳出来。

## 六、日历（Calendar）

### 6.1 功能概述

日历视图将所有有时间锚点的安排（任务与日程）汇聚在同一时间轴上，提供宏观视角。

### 6.2 视图

- **小组件**（右侧面板）：当月的迷你日历，标记打卡日
- **多周视图**：全屏弹窗展示 2-3 周的完整视图

### 6.3 展示方式

- **时间点**（Dots）：单日任务与日程以彩色圆点标识在对应日期下方——粉色为日程，青色为任务，绿色为已完成
- **时间条**（Bars）：跨多日期的任务以水平横条跨越对应日期段，支持多任务并行道次显示
- **详情抽屉**：点击任意日期，侧边栏展开当日的完整安排列表

### 6.4 使用方法

1. 在右侧面板底部的日历组件查看月度概览
2. 点击日历组件打开多周视图
3. 可切换 2 周/3 周显示模式，按月/周导航
4. 点击日期打开详情抽屉，查看和编辑当日安排

## 七、每日打卡（Check-in）

### 7.1 功能概述

每日打卡是轻量级的签到机制。系统在每次访问时自动完成当日打卡（如当天尚未打卡），并追踪累计打卡天数和连续打卡天数（Streak）。

### 7.2 展示

- 顶部导航栏的日历图标旁展示当前连续打卡天数
- 自动打卡后会有庆祝动画反馈

## 八、概念关系总览

```
事件 (Event)
├── 设定时间边界（开始日 ↔ 截止日）
├── 拆解为规划草案 (Plan Draft)
│   └── 生成安排 (Arrangement)
│       ├── 任务 (Task) ──── 需要推进完成的事项
│       └── 日程 (Appointment) ──── 需要守住的时间节点
├── 事件成就 (Event Achievements)
│   └── 追踪事件范围内的里程碑
└── 事件规划模板 (Plan Template)
    └── 可复用的拆解方案

工作流 (Workflow)
├── 定义专注-休息的循环节奏
├── 绑定具体任务或专注工作类型
└── 驱动专注工作 (Focus Work)
    └── 全屏工作台，深度沉浸

专注工作 (Focus Work)
├── 任务专注 (task_focus)
├── 今日单词 (vocab_today)
└── 阅读理解 (erc_review)

成就 (Achievement)
├── 事件成就 —— 在事件的漫长跨度中给予反馈
└── 全局成就 —— 跨事件的累积记录

日历 (Calendar)
└── 汇聚所有安排的时间视图
```

## 九、未实现的设计展望

以下概念来自设计哲学初稿，目前尚未在系统中实现：

- **主旋律（Theme Music）**：为事件绑定一首背景音乐，作为听觉锚点——听到主旋律即可快速进入专注状态。未来计划将其渗透到工作流的各阶段：专注阶段播放主旋律变奏，休息阶段淡出或切换为环境音。
- **子事件（Sub-Event）**：允许事件嵌套，形成层级结构。子事件与父事件拥有相同的结构能力，支持无限嵌套。
- **事件发布会**：未来可能的社交化功能，主旋律可作为其重要组成部分。
