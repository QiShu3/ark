# 工作流学习路径设计草案

## 背景

工作流的预览阶段和结算阶段不应只展示阶段列表或成绩汇总。对于带有扩展学习机制的工作流，用户真正需要看懂的是：

- 接下来要围绕哪个核心任务展开。
- 哪些内容是主任务，哪些内容是可扩展学习。
- 扩展学习完成后会回到哪个任务。
- 实际执行过程中，哪些尝试未达标，哪些尝试达标，最终如何收敛。

因此，工作流应使用类似 Git graph 的路径表达，但文案应尽量避免 `fork`、`主线`、`嵌套` 等术语，改用更贴近学习场景的表达。

## 文案规则

### 顶部结果

- 总结果统一显示为：`完成`
- 不使用：`补强后完成`

### 扩展关系

- `Fork` 对用户展示为：`可扩展学习`
- `返回主线` 对用户展示为：`回到《父节点任务名称》`
- 不使用：`主线`、`回流`、`嵌套 Fork`

### 状态文案

专注任务的状态由是否存在检测机制决定。

没有检测机制时：

- `完成`
- `放弃`

存在检测机制时：

- `达标`
- `未达标`
- `放弃`

不要混用 `完成` 和 `达标`。`完成` 表示任务做完；`达标` 表示通过检测标准。

## 预览阶段

预览阶段出现在“打开工作流之后，专注工作正式开始之前”。

目标是让用户先看到本次工作流的内容结构：核心任务是什么，可以扩展到哪些学习方向。

### 示例：考研英语阅读深度突破

这个示例中，主线上只有一个核心任务：`阅读理解训练`。其它内容都是围绕它展开的可扩展学习方向。

```text
┌──────────────────────────────────────────────────────────────┐
│ 准备开始                                                     │
│ 考研英语阅读深度突破                                         │
│ 1 个主任务 · 预计 70 分钟 · 含 7 个可扩展学习方向            │
├──────────────────────────────────────────────────────────────┤
│ 即将开始                                                     │
│                                                              │
│ ● 阅读理解训练             检测标准 85%                      │
│   └─▶ 可扩展学习：核心词汇辨析                               │
│   └─▶ 可扩展学习：长难句结构拆解                             │
│   └─▶ 可扩展学习：段落逻辑关系                               │
│   └─▶ 可扩展学习：题干定位与选项排除                         │
│   └─▶ 可扩展学习：同义替换识别                               │
│   └─▶ 可扩展学习：干扰项类型归因                             │
│   └─▶ 可扩展学习：篇章主旨与作者态度                         │
├──────────────────────────────────────────────────────────────┤
│ [取消]                                      [开始工作流]      │
└──────────────────────────────────────────────────────────────┘
```

预览阶段不需要单独的“本次规则”板块。规则应通过路径本身和按钮文案表达。

## 结算阶段

结算阶段展示“实际发生了什么”。它不是单纯的统计弹窗，而是学习路径记录。

结算阶段分为两类：

- 专注任务结算阶段：单个任务完成后出现，用于判断本段结果并选择下一步。
- 工作流结算阶段：整个工作流结束后出现，用于回顾完整学习路径。

## 专注任务结算阶段

专注任务结算阶段出现在单个专注任务结束后、进入下一段或扩展学习之前。它的目标不是展示完整工作流，而是回答：

- 这一段是否完成、达标或未达标。
- 这一段的关键数据是什么。
- 现在应该进入下一段、再做一轮，还是进入可扩展学习。

### 无检测机制

没有检测机制的专注任务只展示 `完成` 或 `放弃`。

```text
┌──────────────────────────────────────────────┐
│ 本段结束                                     │
│ 记忆回收                                     │
│ 完成                                         │
│ 9m · 复习 24 个 · 新学 6 个                  │
├──────────────────────────────────────────────┤
│ 本段数据                                     │
│ 已复习 24    已掌握 18                       │
│ 新学 6       用时 9m                         │
├──────────────────────────────────────────────┤
│ [再做一轮]              [进入下一段]          │
└──────────────────────────────────────────────┘
```

### 有检测机制且达标

存在检测机制时，任务状态使用 `达标`、`未达标` 或 `放弃`，不使用 `完成`。

```text
┌──────────────────────────────────────────────┐
│ 本段结束                                     │
│ 阅读理解训练                                  │
│ 86% 达标                                     │
│ 8m · 5题 / 4对 · 标准 80%                    │
├──────────────────────────────────────────────┤
│ 本段数据                                     │
│ 已答题 5     正确 4                          │
│ 正确率 86%   用时 8m                         │
├──────────────────────────────────────────────┤
│ [再做一轮]              [进入下一段]          │
└──────────────────────────────────────────────┘
```

### 有检测机制且未达标

未达标时，重点展示可扩展学习入口。可扩展学习入口应使用配置中的子任务名称，不展示 `fork` 字样。

```text
┌──────────────────────────────────────────────┐
│ 本段结束                                     │
│ 阅读理解训练                                  │
│ 62% 未达标                                   │
│ 12m · 5题 / 3对 · 标准 80%                   │
├──────────────────────────────────────────────┤
│ 本段数据                                     │
│ 已答题 5     正确 3                          │
│ 正确率 62%   用时 12m                        │
├──────────────────────────────────────────────┤
│ 可扩展学习                                   │
│ 高频词汇巩固                                  │
│ 长难句结构拆解                                │
├──────────────────────────────────────────────┤
│ [再做一轮]              [完成并进入下一段]    │
└──────────────────────────────────────────────┘
```

### 可扩展学习任务完成

如果当前任务是从父任务展开的可扩展学习，主按钮应回到父任务，而不是进入下一段。

```text
┌──────────────────────────────────────────────┐
│ 本段结束                                     │
│ 高频词汇巩固                                  │
│ 完成                                         │
│ 6m · 复习 18 个                              │
├──────────────────────────────────────────────┤
│ 本段数据                                     │
│ 已复习 18    已掌握 15                       │
│ 正确率 83%   用时 6m                         │
├──────────────────────────────────────────────┤
│ [再做一轮]              [回到《阅读理解训练》] │
└──────────────────────────────────────────────┘
```

### 交互规则

- `再做一轮` 是次要动作。
- 普通任务达标后，主按钮为 `进入下一段`。
- 普通任务未达标后，仍允许 `完成并进入下一段`，但可扩展学习入口应更突出。
- 可扩展学习任务结束后，主按钮为 `回到《父节点任务名称》`。
- 没有可继续内容时，使用 `暂无可继续内容`，并保留合理的结束或返回动作。

## 工作流结算阶段

工作流结算阶段展示“实际发生了什么”。它不是单纯的统计弹窗，而是学习路径记录。

### 展示原则

- 同一个任务可以重复出现，表示多次尝试。
- 只有扩展学习节点下面才出现 `回到《父节点任务名称》`。
- 终点任务没有扩展学习，也没有 `回到` 节点。
- 扩展学习可以继续展开新的扩展学习。
- 每次完成扩展学习后，应明确回到它的父节点任务。

### 示例：实际执行路径

```text
┌──────────────────────────────────────────────────────────────┐
│ 工作流完成                                                   │
│ 考研英语阅读深度突破                                         │
│ 结果：完成                                                   │
│ 总用时 76m · 1 个主任务 · 4 次可扩展学习 · 4 次再尝试        │
├──────────────────────────────────────────────────────────────┤
│ 过程                                                         │
│                                                              │
│ ● 阅读理解训练             61% 未达标   18m                 │
│   └─▶ ● 长难句结构拆解     82% 达标     9m                  │
│       └─▶ ● 回到《阅读理解训练》                             │
│                                                              │
│ ● 阅读理解训练             72% 未达标   11m                 │
│   └─▶ ● 题干定位与选项排除 80% 未达标   8m                  │
│       └─▶ ● 同义替换识别   90% 达标     7m                  │
│           └─▶ ● 回到《题干定位与选项排除》                   │
│       └─▶ ● 回到《阅读理解训练》                             │
│                                                              │
│ ● 阅读理解训练             79% 未达标   9m                  │
│   └─▶ ● 篇章主旨与作者态度 84% 达标     6m                  │
│       └─▶ ● 回到《阅读理解训练》                             │
│                                                              │
│ ● 阅读理解训练             88% 达标     10m                 │
├──────────────────────────────────────────────────────────────┤
│ 汇总                                                         │
│ 总答题 42 · 总正确 35 · 最好一次 90%                        │
│ 可扩展学习 4 次 · 再尝试 4 次 · 最终达标                    │
├──────────────────────────────────────────────────────────────┤
│ [结束工作流]                                  [查看记录]     │
└──────────────────────────────────────────────────────────────┘
```

## 结构解释

以上结算示例表达了几类情况：

- `阅读理解训练` 第一次未达标，于是进入 `长难句结构拆解`。
- `长难句结构拆解` 达标后，图中出现 `回到《阅读理解训练》`。
- 随后再次出现 `阅读理解训练`，表示回到核心任务后重新尝试。
- `题干定位与选项排除` 自身也可以继续展开 `同义替换识别`。
- `同义替换识别` 完成后，先回到 `题干定位与选项排除`，再回到 `阅读理解训练`。
- 最后一条 `阅读理解训练 88% 达标` 是终点，因此没有扩展学习，也没有 `回到` 节点。

## 信息层级

### 预览阶段

预览阶段建议保留三块：

- 标题区：工作流名称、预计时间、可扩展学习数量。
- 路径区：核心任务与可扩展学习方向。
- 操作区：取消、开始工作流。

### 结算阶段

专注任务结算阶段建议保留四块：

- 标题区：任务名称、状态、核心结果。
- 数据区：本段答题、正确、正确率、用时等。
- 可扩展学习区：仅在未达标且存在子任务时展示。
- 操作区：再做一轮、进入下一段、完成并进入下一段、回到父任务。

工作流结算阶段建议保留四块：

- 标题区：工作流名称、结果、总用时、执行次数摘要。
- 路径区：实际执行路径。
- 汇总区：总答题、总正确、最好一次、可扩展学习次数、再尝试次数。
- 操作区：结束工作流、查看记录。

## 后续实现提示

预览阶段使用工作流配置数据即可生成。结算阶段需要后端返回比当前阶段汇总更细的运行路径数据，至少包含：

- run id
- parent run id 或 source run id
- run 名称
- run 类型
- 是否存在检测机制
- 状态：完成、放弃、达标、未达标
- 正确率
- 用时
- 回到的父节点名称

前端应基于这些数据构造路径图，而不是只按阶段数组平铺。
